Requests rarely fail loudly. They stall quietly between two people who each think the other has it. Relay is a workflow board concept built around handoffs. This is a dummy write-up while the real case study is on its way.

## The problem

Boards show where work is, but not who it is waiting on. A card can sit in “In progress” for a week while the real blocker is a question nobody answered.

## The approach

Relay makes the handoff the primary object. Every request has exactly one owner at a time, a clear next step, and a visible clock for how long it has waited.

- A single owner per request, always.
- Waiting time is shown, not hidden.
- Closing a request asks what was learned.

> “Work doesn’t get stuck in columns. It gets stuck between people.”

## What it could become

A lightweight API for intake, automations for routine handoffs, and reports that show where requests wait the longest.

<Takeaway title="Where it could go">

Make ownership obvious and the board mostly takes care of itself. The rest is removing the reasons a request has to wait.

</Takeaway>
